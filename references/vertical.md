# 竖屏 9:16：坐标、字幕、旁白对齐

> 当前新工程使用纯 Remotion：尺寸与时长来自 `motion.json`，字幕在 `remotion/src/components/Subtitles.tsx` 统一排版，并在字体加载后测量 DOM 边界。下文的 `film.js`、Canvas 字体调用和 `index.html` 配置只用于旧引擎；坐标、可见字数、旁白对齐和底部安全区同样约束新引擎。M01 暖纸底采用深色字幕。

本工作流只出 **1080×1920 / 30fps** 的抖音书评短片，声音只有温暖男声旁白。
横屏的那套跑道（仪表航道、y≤770 信息底线）不适用，以这一篇为准。

## 一、画幅怎么生效（两处必须一致）

- `index.html`：在 `engine/vk.js` **之前**写 `<script>window.VK_SIZE=[1080,1920];</script>`（`new_film.py` 生成的已经写好）。
- `engine/render.py` 自动读这个声明决定截图尺寸，不用手动加 `--size`；`--jobs 4` 的子进程也会带上。
- 改了画幅就重渲：旧 mp4 不会被自动发现尺寸变了，`check_film.py` 会查。

## 二、三条竖屏跑道（硬约束）

```
1080 × 1920
┌──────────────────────────┐
│ 顶部小字区 y 90–200        │  作者 / 书名 / 章节，x=62 起，最多两行
│                          │
│ 内容区 y 240–1380          │  主体、道具、对比，都在这里发生
│                          │  主体中心别压在正中央（960）不动，留白也是内容
│ ────────────────────────  │  y=1400 起字幕底板渐暗（只有地面、远景可以伸下来）
│ 中文主行约 76–78%H          │  参考片实测 76–78%；本工程单行中心约 y=1500
│ 英文副行约 81–84%H          │  可选，只在中文单行时出现
│                          │
│ 底部留空 y≥1600           │  约 18% 给抖音 UI：标题、进度条、按钮
└──────────────────────────┘
左右边距 ≥60；一镜最多一条小字；任何时刻只有一个主体在动。
```

参考片是 3:4，中文主行中心 76–78%、英文副行 81–84%、账号名 93–95%；本工作流是 9:16，按同一相对高度落位，但底边仍压在 0.83H 以内，给抖音 UI 让路。

- 所有字幕位置只认 `film.js` 里的 `const SUB_Y = 1500`，不要逐行写 y。
- 想抬高字幕就改 `SUB_Y`，同时把 `subBackdrop` 的渐变起点（1400）一起挪，保证字有底托。
- 底部留空不是浪费：那是抖音界面要盖住的地方，关键信息一个像素都别放下去。

## 三、字幕规格

| 项 | 值 |
|---|---|
| 内容 | 就是旁白原文，按真实停顿拆短，不改写、不额外加"金句" |
| 字号 | 68（≤13 字）/ 62（14–16 字）/ 54（>16 字）；行距 = 字号 ×1.38 |
| 行数 | 最多两行；一行 ≤18 字，推荐 8–14 字（超过就拆成两条字幕） |
| 英文副行 | 可选；中文单行时在下方加 27px 一行，≤60 字符，只作屏显不配音 |
| 染色 | 一句最多一处：`{词}` 金色（关键意象），`{!词}` 玫红（痛感词），不要句句都染 |
| 位置 | 块中心 `SUB_Y=1500`；中文主行约 76–78%，英文副行约 81–84%，底边不超过 1594 |
| 进出场 | 淡入 0.26s、淡出 0.2s；两条字幕之间不重叠 |
| 永远最后画 | `subBackdrop(fr)` → `drawSubs(fr, t)` 放在 `draw` 末尾，压在一切之上 |
| 书名卡 | 顶部 `今日分享 / 书名 / 作者` 用 y≈292–462，淡入 0.45s；书名卡期间不让字幕压上去 |

## 四、时间从旁白来，不是先排秒数

1. `scripts/make_voiceover.py` 生成 `audio/timings.json`：每段的 `start/end/dur`，以及全片 `duration`。
2. `film.js` 的 `DUR = duration`，场景切点 `T` 按分段边界定；`new_film.py` 在 timings 存在时会自动带入。
3. 字幕切点要比分段更细：以 `audio/vo/*.wav` 的**真实停顿**为准（看波形静音段，或边听边记），
   一句说到哪，字幕就到哪；不要整段一句挂七八秒，也不要平均切。
4. 旁白说完后留 `TAIL`（默认 2 秒）给片名卡和余韵，这段时间没有字幕、没有声音，画面自己收。

## 五、没有配乐，节奏靠什么

- 靠**旁白的停顿**：分段 `gap`（0.8–1.2s）就是呼吸，不要用画面把它填满。
- 靠**画面的落定**：主体出完之后停住让人读；重要的那一下之后给 0.5–1 秒几乎不动。
- 靠**转场的深浅**：`K.dips` 或自写 DIP，断章才压深，同一条情绪不断线就轻压。
- **禁止**用音效补节奏：不写 `fr.sfx`，不加 BGM，不在后期垫任何音乐。`check_film.py` 会查。

## 六、竖屏特有的毛病

- 把横屏构图直接缩小放进竖屏 → 主体太小、上下大片空白。竖屏要重新安排"上下关系"：天/地、台上/台下、灯/人。
- 字幕贴底（y≥1634）→ 被抖音 UI 吃掉。这是被用户打回过一次的问题，别再犯。
- 顶部小字和主体抢位置 → 主体往上长到 y<200 时，小字要先退场。
- 画面很满、字幕压在复杂纹理上 → 检查 `subBackdrop` 有没有画、亮度够不够。
- 自查用原尺寸静帧：`--stills` 抽一张两行字幕的时刻，量字底边；再缩到手机宽（约 360px）看还认不认得出主体。
