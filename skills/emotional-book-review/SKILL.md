# 情感书评文案

默认简体中文、8–15分钟叙事讲解型深度书评，先以预计10–12分钟构思，温暖克制男声；让叙事和分析共同推进一个问题，时长随材料调整。用户指定短篇、评论体、金句书摘体或情感散文体时按要求写；短篇情绪导读不要求完整论证。

默认长稿必须读取 [references/NARRATIVE_LONGFORM.md](references/NARRATIVE_LONGFORM.md)：确定范围及剧透边界，建立叙事与证据底稿，先设计章节提纲，再撰写与审查完整口播。以下情绪线和短稿步骤仅在短篇情绪导读时优先使用；事实与引用规则适用于所有稿件。

## 1. 输入与事实底稿

读取书名、作者、用户摘录或笔记、目标时长、平台、受众、人称、剧透边界。缺省为抖音/视频号通用、尽量不剧透关键转折。用户明确要求优先；无须追问非必要参数。需求卡见 [assets/INPUT_TEMPLATE.md](assets/INPUT_TEMPLATE.md)。

先区分材料性质，再决定写作范围：

| 材料 | 可做什么 | 不可推导什么 |
|---|---|---|
| 可读取的原书正文、带出处的书页或授权试读 | 核对片段、人物行动和逐字引文 | 一个片段不等于掌握全书 |
| 用户笔记、简介、评论及有把握的作品基本信息 | 标明来源后转述可确认内容、提出解读；有工具时核查具体事实 | 笔记、他人评论不是原著逐字文本 |
| 仅书名或出处不明的网络金句 | 查证；查不到时排除未核实内容 | 不能凭记忆补作者、情节、结局或名句 |

底稿保留：本条讨论的问题、可确认的事实锚点、材料来源、待核实项。事实与自己的判断分栏记录。参考视频或ASR转写仅是写法样本；其中句子不能凭“出现在某本书的视频里”就升级为原著引文。
来源不足但主题明确时，可给“主题向灵感稿”，不包装为精准书评。书名和主题都不明时，说明需要简介；不硬凑成稿。
不声称读过未提供的全书，不虚构个人阅读史、亲历或读者共同经历。

## 2. 原文引用：先核查，再选用

写作前阅读 [references/QUOTING.md](references/QUOTING.md)。为每条候选引文建立引用记录：原文、书名/作者、译者/版本、位置、上下文/说话者、核实依据、状态、使用理由。
区分“已核实原著引文／用户提供片段／二手引述待核／原创评论”。未知字段写未知，不伪造页码。

只有能与文本对应的内容才使用“书里写道”和作者署名。用户要求使用未经核实的名句时，说明不能确认并排除该句，继续完成有依据的部分。
不能确认的名句，不是去掉引号就能使用。只有观点或情节另有可靠支持时，才能转述那些已确认内容；没有支持就删除。
短稿通常一句关键短引已足够，也允许零引用；长稿按评论需要增加。数量是编辑参考，不是必须凑齐的配额。
选句须支撑本条判断，并在前后交代情境与自己的解释。没有推进作用的名句删掉。
引用太长时选取连续、语义完整的短片段，不改字凑字幕；不把人物台词当作者主张，不拼不同译本。
原创评论不加作者署名；署名只对应明确标出的真实引文，不能覆盖整段混合文案。

## 3. 先定一条情绪线，再写正文

写短视频导读前阅读 [references/EMOTIONAL_LEAD.md](references/EMOTIONAL_LEAD.md)。内部先填一张编辑卡，不放进配音正文：

| 项目 | 要确定的内容 |
|---|---|
| 观众处境 | 想靠近却后退、想告别却仍等待等一个具体矛盾，按材料确定 |
| 目标观众 | 谁会在什么关系或处境中感到这一矛盾；未指定时根据可靠材料作有限推测 |
| 书籍锚点 | 能支撑这个矛盾的一个片段、动作、关系或准确概念，并记来源 |
| 推进 | 中间发生什么变化，或观众会多理解哪一层 |
| 落点 | 开头的问题最后停在哪里；可不解决，不必安慰 |

入口、正文、结尾共享这条线。材料有其他更合适的结构时按内容调整，不把编辑卡变成四段填空。

内部比较少量切口，选一个有证据、能展开的问题：
- 人物在具体处境下做了什么？这个行动有哪些矛盾？
- 一个物件或叙事细节，为什么在这里出现？
- 一个概念能解释什么，又解释不了什么？

短稿优先围绕一个片段推进，用1–2个可信锚点；材料只有一个片段时就只谈该片段，不概括整部作品。不同细节并用时，需要能说清它们怎样推进同一个问题。
一篇形成一个有细节支撑的原创理解，可以藏在对照、措辞和收尾里，不必宣布“我认为”“这说明”。不能只复述剧情，也不能只靠书名和人名维持辨识度。
通常从情感共鸣、文学治愈、遗憾告别、人生感悟中选择，可有一个轻度副风格；用户指定其他情绪时按其要求。选择参见 [references/STYLE_GUIDE.md](references/STYLE_GUIDE.md)。
情绪服从文本，温暖声线不要求温暖结论，不强行安排释怀或励志。

默认内部比较至少两种入口：一种从观众处境进入，一种从有依据的书中行动或关系进入；材料不支持其中一种时改用有依据的观察，并说明不足。选择最具体、与书籍锚点连接最自然、后文能兑现的入口；除非用户要求比较，不必交出候选稿。开头可以直接陈述；吸引力来自具体张力，不靠“认知越高”“读懂就能”等承诺。
书名尽早自然出现一次，可简短口播，也可由书名卡承担；不强制“今日分享”。口播引书与同步书名卡可以并存，后文不重复报幕。
正文先给必要情境，再让动作、关系、概念或一个核心意象发生变化，接上自己的理解。情绪导读的评论可短；用户要分析时保留充分解释。长短句随听感搭配，不要求句句成金句，不固定句数和四拍秒数。
结尾接住入口的情绪或问题，停在动作、意象、疑问或有限判断。若前一句已完成表达，就在那里收住，不再补同义总结、劝告或回暖。金句书摘体也需一条贯穿的理解，不能拼凑出处不明的名句。

## 4. 两轮编辑，再朗读

先完整写自然口播，不按字幕宽度截断思路。编辑示例见 [references/EXAMPLES.md](references/EXAMPLES.md)。

第一轮检查事实与引用：
- 每个情节和关系能找到来源吗？没有就删除，不以“据说”“也许”掩盖。
- 引文逐字、译本、说话者和语境是否匹配？有没有删改否定、条件或讽刺含义？
- 原创判断是否被误标成作者原话？只给自己能支持的解读。

第二轮检查文案质量：
- 替换书名和人物名后，全文是否仍可原样用于别的书？若可以，回到具体锚点重写。
- “孤独、成长、释怀”等判断是否有行动、关系或文本细节支撑？
- 删去一句“这就是人生”“这句话道尽……”后，有没有损失信息？没有就删。
- 相邻句是否只是换词重复上一句？整齐排比、连续反转是否挤掉了解释？
- 开头提出的困境是否由本书片段接续？中段有没有带来新变化？结尾是否接住它，而非另起大道理？
- 标题与首句向目标观众提出的期待，是否由书中细节和结尾兑现？逐句判断新增的动作、关系或理解；只重复已有信息的句子删去。判断过大而细节支撑不足时缩小判断，不补造情节。
- 将“我更在意的是”“这让我们明白”等解释去掉后，动作和句间关系还能否传达理解？能就直接呈现；缺桥梁时补一句必要解释。
- “现有笔记只告诉我们”“材料不足”等编辑说明是否混进口播？把范围说明放在正文之外，正文只在已知范围内写。
- 生活映射是否盖过原著？不能用随处可套的“深夜删消息”等细节替代书籍分析。
- 有没有伪造个人经历、强行替所有人发言或给痛苦安排好处？改成有分寸的观察。
- 不靠随机加语气词、错别字或故意不通顺制造“人味”。

最后朗读：检查指代、因果、呼吸和拗口处。可读性优先于修辞密度。
时长仅估算：默认8–15分钟，先以10–12分钟构思；用户时长优先，内容自然结束优先于凑数。目标总秒数先减去片头、片尾及停顿，再按约4–5字/秒粗估口播量；不同声线和情绪须实测。材料少就补充资料、缩小范围或交较短稿并说明，不编内容凑时长。
没有实际朗读/音频测量时写“预计”，不能声称已验证秒数；正式配音仍等用户确认。

## 5. 输出与确认

默认交付本期切口、剧透说明、章节提纲、成稿、3个标题、配音提示和简短来源说明；有引用时补充核实状态，有材料限制时说明范围。不要展示内部推理或评分。

```markdown
**书籍**：《书名》／作者（已确认时）
**风格与叙述体**：……（默认叙事讲解型深度书评）
**预计时长**：……（未配音测量）
**本期切口与剧透说明**：……

### 章节提纲
[各章节的叙事内容及带来的理解]

### 书评口播文案
[自然分段、可直接朗读的正文；真实引用用引号区分，不含时间码和表演指令]

**备选标题**：……／……／……
**配音提示**：……
**引用依据**：[有引文时：逐条给版本、位置、来源及核实状态；无直接引用时写“无直接引用”]
**材料范围**：[存在限制时，说明只依据哪个片段／哪些笔记]
```

英文副行改为可选，按用户或已有工程要求生成，不影响中文写作；只作屏显，不配音。扩展交付见 [references/OUTPUTS.md](references/OUTPUTS.md)。
纯文案请求只输出干净正文；引用记录仍内部保留，正文也不得将未核实内容伪装成原话。
批量或多风格版本分别选切口，不只换形容词；按来源逐本核查。

成稿交给用户后停在文案环节。用户确认后才交回视频工作流写 script.json、配音、分镜和建工程；用户只要求修改时仅改文案。
确认后只把正文送入配音，引用依据另存项目事实表。字幕按语义拆分，每个完整句可以跨多屏；拼接后保持正文原字原序，尤其不能改写引文。

需要评估表达或传播时，按 [references/REVIEW_AND_FEEDBACK.md](references/REVIEW_AND_FEEDBACK.md) 做听众试读和发布后复盘；有真实反馈才记录结果，不虚构盲测、发布或数据，也不因缺少数据阻塞普通文案交付。
